# 报价与成本模型（与工作台 `calculate()` 一致）

工作台是**成本加成**报价：填含税采购价、税率、费用、目标利润率，反推外销单价。不是把采购价当卖价。

## 1. 单件真实成本

```
不含税采购价 = 含税采购价 / (1 + 增值税率)
退税额       = 不含税采购价 × 出口退税率
实际采购成本 = 含税采购价 − 退税额
```

## 2. 费用进入成本的范围（按贸易术语）

| 费用 | 进入条件的术语 |
|---|---|
| 国内段（报关/拖车） | FCA、FAS、FOB、CFR、CPT、CIF、CIP、DAP、DPU、DDP |
| 国际运费 | CFR、CPT、CIF、CIP、DAP、DPU、DDP |
| 保险费 | CIF、CIP、DAP、DPU、DDP |
| 银行/杂费 | 始终计入 |

EXW 下三者都不计，只计银行费。

## 3. 费用分摊到每个 SKU

- 国内段：按 `domestic_alloc` 选数量 / 体积 / 重量分摊。
- 国际运费：拼箱按 CBM；空运按计费重（`max(实重, CBM×167)`）；整柜按数量。
- 保险费、银行费：按 `domestic_alloc` 同一基准分摊。

```
单件分摊费 = 费用总额 × (该SKU的基准量 / 全部基准量) / 该SKU数量
```

## 4. 报价单价

```
单件总成本(CNY) = 实际采购成本 + 国内分摊 + 国际分摊 + 保险分摊 + 银行分摊
目标单价(CNY)   = 单件总成本 / (1 − 目标利润率)
外销单价        = 目标单价 / 汇率
外销单价        = ceil(外销单价 / 取整精度) × 取整精度
```

默认取整精度 0.05。JPY 等零小数币种强制按 1 取整，避免“单价 × 数量 ≠ 总额”。

整单折扣在取整之后乘 `(1 − 折扣%)`，再四舍五入到分。

## 5. 算例（`assets/demo-shipment.json`）

参数：CIF、汇率 7.2、增值税 13%、退税 13%、利润率 20%、国内 1500、海运 8000、保险 200、银行 500、按数量分摊。

**SKU 1：Smart Watch X1，3000 件，含税采购价 150**

```
不含税     150 / 1.13            = 132.7434
退税       132.7434 × 13%        =  17.2566
实际成本   150 − 17.2566         = 132.7434
分摊费     (1500+8000+200+500) × 3000/5500 / 3000 = 1.8545
单件成本   134.5979
目标单价   134.5979 / 0.8        = 168.2474 CNY
外销单价   168.2474 / 7.2        = 23.3677 → ceil 0.05 → 23.40 USD
```

**SKU 2：Bluetooth Speaker S2，2500 件，含税采购价 210**

```
实际成本   210 / 1.13            = 185.8407
分摊费     同上                  = 1.8545
单件成本   187.6953
目标单价   234.6191 CNY / 7.2    = 32.5860 → 32.60 USD
```

合计：`3000 × 23.40 + 2500 × 32.60 = 151,700 USD`；折人民币 1,092,240，总成本 873,031.86，实际利润率约 20.07%（取整带来的偏差）。

## 6. 如果客户已经给了目标卖价

工作台没有“手工锁定单价”输入，用反推利润率：

```
目标利润率 = 1 − 单件成本(CNY) / (目标卖价 × 汇率)
```

把算出的 `margin_rate` 填进 `costs.margin_rate`，再核对每行单价。多 SKU 且各自目标利润率不同时，一个整单利润率无法同时命中；此时按主要 SKU 反推，其余行用四舍五入后的差异在合同/备注中说明，或拆成多张 PI。

## 7. 常见错误

1. 把**卖价**填进 `unit_price_cny`——会再按利润率加价一次，报价虚高。
2. 退税率填成增值税率——多数产品退税率等于征税率，但不总是；以商品编码的退税率文件为准。
3. 运费重复计入——CIF 已含海运，又在单价里加一次。
4. 忘记银行费/保险——小额单尤其明显。
5. 用 0.01 精度报低价货——单价被向上取整放大；大批量时改用 0.001 或按总额报价。
